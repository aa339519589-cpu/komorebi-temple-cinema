原图和该实际帧重建桥—梯—岸的完整路线。没有把 depth128 远移方案落地。

## 实际图的版本必须分清

- **B1 原机位**：`iteration-watercourt131-reference/reference.png`。真实图
  暴露前岸抬土/岩石过量、红灌木挡桥及西平台岸壁过大，仍是失败候选。
- **B2 最终侧视**：`iteration-watercourt131-side/inspection-view.png`。
  在 B1 之后取消西平台整片填土/实心脚板，改六个独立石脚；水槽保持
  开放，前岸回到较低地形并保留窄挡水石岸，前侧灌木降矮/整组改位。
  两张图的源不同，`B1-source/` 保存变化前四个完整源文件。
- **B2 最终原机位未复验**。不能把 B1 原机位图当作最终 B2 原机位结果，
  也不能以侧视证明参考照片的布局比例已匹配。

`reference-A-B1-overview.png` 和 `reference-A-B1-route-native.png` 直接比较
原图、A 实际帧及 B1 实际帧；原生局部保持原始像素。B2 侧视是现有真实
3D 场景的独立机位，没有投影照片、贴平面或替代图。

## 已处理的穿插与整株改位

- 在附廊楼板中开真正的梯槽，并把门洞移到梯头，去除旧梯段穿楼板关系。
- 近景左灌木外移到 (−3.4,8.6)，红枫整组移到 (13,−18)，前右灌木
  降矮并移到较低岸边，减少近栏杆和桥前遮挡。
- 按实际木构/栏杆的世界坐标边界剪整枝和细枝，随机样本顺序保持。
  松树重新接地到 (2.7, terrain(2.7,−11.3)−.035, −11.3)，重排主枝，
  剪除20条碰界细枝，实际保留35,200束真实针叶。没有屏幕空间抠叶片。
- 其他植物执行270次阻挡枝梢查询。这是剪枝记录，不是270处互不重复的
  穿插证明，更不是全场景无相交保证。

侧视仍可见岸坡/石脚块面和木石接合生硬，上层翼廊开口、墙窗及主殿
高台基也显得不完整。桥与水院在最终原机位中的可见比例、细叶与木构
邻近处仍未验收；材质、光影、植物质感与 HD 原图仍有明显距离。两次
GPU 有效出图及有限几何检查不构成照片级验收。所有十个场景仍未完成。

## 实渲命令

```sh
REFERENCE=8 SIZE=1254 ITERATION=watercourt131-reference PORT=4742 node tools/render-one-reconstruction.mjs
REFERENCE=8 SIZE=1254 ITERATION=watercourt131-side PORT=4743 VIEW_POSITION=12,7,-2 VIEW_TARGET=-1,5.5,-7 VIEW_FOV=58 node tools/render-one-reconstruction.mjs
```

原机位与侧视均经共享 GPU mutex。`source-provenance.json` 记录 A、B1、B2
源身份、截图哈希和版本差异；两个 render receipt 的 `sourceCommit` 是
渲染前的 A 提交，精确候选以其完整源哈希为准。
